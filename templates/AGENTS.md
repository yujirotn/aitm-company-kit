# 会社の前提とルール（AIが毎回最初に読むファイル）

このフォルダは、建築会社の業務をAIの「チーム」で進めるための作業場です。
AIは作業を始める前に、必ずこのファイルを読んでください。

- 会社名: （ここに記入）
- 事業: （例: 注文住宅の設計・施工）
- 使っているソフト: ArchiTrend、ホームズ君、Excel、OneDrive、LINE公式、ほか

## チームの役割

役割ごとの詳しい指示は、プラグインの役割（サブエージェント）として入っています。担当する作業に応じて、その役割を呼び出して動きます。

| 役 | 呼び出し名 | ひとこと |
|---|---|---|
| 統括 | company-lead | 窓口。全体を回し、記録を残す |
| 積算 | estimator | 数量と原価を出す |
| 見積作成 | quote-writer | 売価を決め、見積書にする |
| チェック | reviewer | 作った役とは別の目で検算する |
| 顧客対応 | customer-care | お客様とのやりとりと案件の経過を管理する |

ユーザーからの依頼は、まず「統括」が受けます。

## 案件ごとの記憶（最重要）

**AIは前の会話を覚えていません。覚えているのは、ここに書かれたことだけです。**
そのため、記録を残すことが仕事の一部です。

案件は `案件/` の中に、案件ごとのフォルダで管理します。

### 作業を始めるとき
1. `案件/案件一覧.md` で対象の案件を特定する
2. その案件の `README.md`（現状・決定事項・未解決）を読む
3. `経過ログ.md` の末尾10件ほどを読む
4. 読んだ内容を一言で言い直して、認識が合っているか確認してから進める

### 作業を終えるとき・区切りのとき・止まる前
1. `経過ログ.md` に追記する（日付・誰が・何をしたか・次にやること）
2. `README.md` の「現状」「未解決」を最新にする
3. 決まったことは、理由と一緒に `README.md` の「決定事項」に足す
4. お客様や業者とやりとりがあれば `やりとり.md` に追記する

### 記録のルール
- **追記が基本。過去の記録は消さない。** 間違いは、訂正を新しく書き足す
- 日付を必ず付ける（例: 2026-10-10）
- 「たぶん」「未確認」は、そう書いたまま残す。推測を事実として書かない
- 金額・数量は、根拠の資料名を添える

### 新しい案件を始めるとき
「新規案件」と言われたら、統括が次を行います。
1. `案件/_テンプレート/` を複製し、`案件/YYYY-MM_案件名/` にする
2. `README.md` の上の欄を埋める（お客様名、物件、状態）
3. `案件/案件一覧.md` に1行足す

## 学んだことの残し方

- 案件に固有のこと → その案件のフォルダ
- 全部の案件で使えること → このファイルの「学んだこと」に1行足す
- 手戻りが起きた → `振り返り/` に1行書き、再発を防げるならルールにする
- うまくいった手順 → `手順書/` に1本のファイルにする

## 守ること

- 金額・数量を出すときは、仮の値と確定した値を必ず分けて書く
- お客様の個人情報は、この会社のフォルダの外に出さない
- お客様や業者へ送る文面は、案を作るところまで。送信は人が確認してから行う
- 分からないことは、推測で埋めずに「未確認」と書いて人に聞く
- 削除・上書きの前に、対象を見て確認する
