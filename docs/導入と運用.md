# 導入と運用

## 状態を先に判定する

AI は対象の作業フォルダを人に確認し、`AGENTS.md`、`導入状態.md`、`会社設定.md`、`顧客/`、旧形式の `案件/` を読み取る。別リポジトリや既存の会社フォルダを勝手に作業先にしない。

| 状態 | 判定 | 次の動き |
|---|---|---|
| 未導入 | 導入ファイルがなく、既存データとの衝突もない | 聞き取り、提案、承認後に作成 |
| 未完了 | `導入状態.md` が未完了、または一部のファイルだけある | 既存内容と残課題を読み、差分だけ提案して再開 |
| 導入済み | 状態が導入済み、必要な参照先が存在する | 通常作業。再設定は明示依頼時のみ |
| 旧形式・不整合 | 旧 `案件/` がある、状態ファイルと実体が矛盾、別の `AGENTS.md` がある | 変更を止め、共存か移行かを人に提案。自動移行しない |

`/company-setup 再設定` は導入済みの設定変更である。現状と変更案の差分、既存ファイルへの影響を示し、人の承認後に対象行だけ更新する。本人の編集、過去ログ、原本、旧版を消さない。変更履歴を `導入状態.md` に追記する。

## 初回の聞き取りと提案

一度に全て埋める必要はない。まず次を質問し、回答・未確認・本人が不要と判断した項目を区別する。

1. 会社・利用者: 事業、扱う案件、利用者の人数、呼び方、既存フォルダ・ツール、データ保存先と権限。
2. 仕事の流れ: 入口、担当、レビュー、最終承認、顧客への送信、よく使う成果物、案件の状態と完了条件。
3. 記録: 顧客と案件の識別子、議事録・やりとり・図面・見積の保管先、原本と改訂の扱い、既存データの移行希望。
4. 見積を使う場合: 原価の範囲、金額が税抜か税込か、税率・適用時点、丸め単位と順序、仮単価と確定単価、**売価に対する粗利率**か**原価への上乗せ率**か。両者を「利益率」で一括りにしない。
5. 安全運用: 個人情報の範囲、バックアップ、公開リポジトリとの分離、外部送信と承認の責任者。

AI は回答から、役割名・担当範囲・入力・成果物・停止条件・引き渡し先、使うフォルダ、承認点を短い構成案にする。既定の5役は積算向けの例として示し、不要な役を外したり、役名・分担を変えたりできる。[構成提案テンプレート](構成提案テンプレート.md)を使って、実装先で表示できるテキストツリー図を人に見せる。打合せメモ、受領図面、改訂図面、業者見積の保存先を具体例で示し、既存の管理との対応・維持する点・変える点を表にする。「この管理方法でいいですか？変更したいところはありますか？」と聞き、修正希望があれば図を直して再提示する。作業先と提案全体への明示合意を得るまでテンプレートのコピーも実データの変更もしない。重大な未確認項目が残るときは `導入状態.md` を未完了とし、該当業務を実行しない。分かった範囲の記録用土台は、承認された部分だけ作ってよい。

## 役割指示を作業先に残す

採用した役割ごとに `templates/役割/_役割テンプレート.md` を基に、作業先の `役割/<役割ID>.md` を作る。プラグインの `agents/` は積算向けの初期案であり、本人の回答に合わせて名前、担当範囲と境界、入力、成果物と保存先、止めて人に聞く条件、確認・引き渡し先、関連手順書を具体化する。役割 ID は重複しない英数字とハイフンとする。必要な手順書がなければ作業先の `手順書/` に作り、役割 MD を起点とした `../手順書/<手順名>.md` で参照する。`AGENTS.md` と `会社設定.md` からは作業先ルート起点の `手順書/<手順名>.md` を使う。対応する `会社設定.md` と `AGENTS.md` の採用役割表にも実在パスを記入する。導入の再開時は既存の本人編集を読み、差分だけ提案する。外した役割の MD は削除せず、履歴を残す。

Codex などでは `AGENTS.md` → `役割/<役割ID>.md` → `../手順書/<手順名>.md`（役割 MD 起点） の順に作業先だけで読めるようにする。参照先が欠けていればその役割の処理を止める。元リポジトリの `agents/` やプラグインへの参照だけで完了としない。

Claude Code で役割をサブエージェントとして呼ぶ場合は、**作業先の** `.claude/agents/<役割ID>.md` に次のようなプロジェクト用定義を作る。`name` と `description` は採用した名前と用途に合わせ、本文では作業先の正本を最初に読むことと、参照できないときに止めることを明記する。

```md
---
name: example-role
description: 確認済みの担当範囲に限って作業する役割
---

最初に作業先の AGENTS.md、会社設定.md、役割/example-role.md と、その役割 MD が指定する手順書を読む。参照先がない、担当範囲が未確認なら作業を止めて人に確認する。役割/example-role.md を正本として従う。
```

プロジェクトの `.claude/agents/` はプラグインの `agents/` より優先される。新しい担当者が見つからないときは Claude Code を再起動し、名前を指定して呼び出して確認する。再設定で役割を外す場合は、本人の確認後に `.claude/agents/` の定義を発見対象外へ移し、旧版を保管する。正本と呼び出し用定義が食い違えば導入状態を未完了とし、差分を確認する。([Claude Code の公式説明](https://code.claude.com/docs/en/sub-agents))

## 保存先と通常運用

標準形は `顧客/<顧客ID>/案件/<案件ID>/`。別の構成を承認した場合は、`会社設定.md` に顧客・案件の保存先と一覧・台帳の対応表を記録し、各コマンドはその設定先を使う。対応が未確認なら作成・更新を止める。ID は顧客内・案件内で一意の中立的な識別子（例: C001、P001）を選ぶ。個人名や住所をパスに含めない。顧客の情報はその顧客の README と案件一覧だけに置き、案件の図面・見積・議事録を別顧客へ参照しない。`顧客/顧客一覧.md` と各顧客の `案件/案件一覧.md` に相対パスを記録する。

案件作成時に `議事録/`、`図面/`、`見積/` を README とともに作る。議事録は日付と通番で追記し、決定・未決・担当・期限・次アクションを分ける。図面は受領した原本を変更せず、改訂版を別ファイルにする。`図面/README.md` の版台帳に出典、受領日、状態、最新版参照先を記録し、人が確定していない版を「確定」としない。見積は原価資料、算定、顧客向け版を分け、旧版を残す。作業後は `/log` 相当で経過を追記する。

未確認の顧客IDや案件ID、同名・重複、資料の出典、図面の採用版、見積方針がある場合は、当該作成・参照・計算を止めて人に確認する。推測で別案件の資料を流用しない。

## プラグインを使わない AI

この文書と `templates/AGENTS.md` を先に読む。初回の聞き取りと提案が終わったら、`templates/` の `AGENTS.md`、`CLAUDE.md`（Claude のみ）、`導入状態.md`、`会社設定.md`、`顧客/`、`役割/`、`単価マスター/`、`手順書/`、`振り返り/` を作業先へ差分確認のうえコピーする。既存ファイルはコピーで上書きしない。`agents/` の役割文書は初期案として必要なものだけ読み、採用した役割ごとに作業先の `役割/<役割ID>.md` を完成させ、`AGENTS.md` と `会社設定.md` に実在パスを記入する。コマンドの文書を手順として読めるが、プラグイン専用パス変数は手元のリポジトリ内 `templates/` に読み替える。

Git 管理する作業先では、実顧客情報を含む `顧客/`、`会社設定.md`、`単価マスター/` などを公開先へ push しない設定を人と確認する。`.gitignore` があっても既に追跡中のファイルには効かない。匿名例だけを公開する。
