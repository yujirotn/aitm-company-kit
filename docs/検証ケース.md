# 検証ケース

`python -m unittest discover -s tests -v` は、マニフェスト・参照・テンプレート構造・計算例の**静的確認**と、匿名の一時フォルダでテンプレートをコピーする**ファイル操作の模擬チェック**を行う。これは AI が実際に聞き取り、適切な判断・コマンド実行をした証拠ではない。Claude Code のプラグイン起動と Codex の実際の対話起動は未検証であり、以下は人と試す際の受け入れ条件である。

| ケース | 入力 | 期待結果 |
|---|---|---|
| 初回 | 空の専用フォルダで `/company-setup` | フォルダ確認と聞き取り、匿名例を入れたツリー図と既存管理との対応表を提示。明示合意後に土台と役割 MD を作る。未確認の見積方針では金額確定をしない |
| 承認前 | ツリー図の提案中に変更希望または無回答 | 図と対応表を直して再提示する。明示合意まで実ファイルを作成・変更しない |
| 途中再開 | `導入状態.md` が未完了、既回答と一部ファイルあり | 既回答を再利用し、残りだけ質問。本人が編集した AGENTS・役割 MD・手順書を保持 |
| Codex の単独利用 | テンプレートをコピーし、採用役割の MD と手順書を作成した後に元リポジトリを参照できない | `AGENTS.md` → `役割/<役割ID>.md` → `手順書/<手順名>.md` を作業先だけで辿れる |
| Claude の新担当者 | 作業先 `.claude/agents/<役割ID>.md` を作成 | 名前を指定して呼び出し、作業先の役割 MD を読む。見つからなければ再起動して再確認 |
| 既存導入 | 導入済みで通常の案件作業 | 再設定せず、対象の顧客ID・案件IDと記録を確認して継続 |
| 複数顧客・複数案件 | C001/P001、C001/P002、C002/P001 | 3つの独立した案件フォルダと顧客別一覧。どの台帳も別顧客へ書かない |
| 議事録追加 | C001/P002 に会議を追加 | 当該 `議事録/YYYY-MM-DD_連番.md` に決定・未決・担当・期限・次アクション。README と経過ログに参照 |
| 図面改訂 | C002/P001 の原本の後に改訂版を受領 | 原本を保持して別版を追加。採用確認まで最新版参照は未確認。確認後に台帳と案件 README を更新 |
| 再設定 | 導入済みで `/company-setup 再設定` | 変更差分・影響を提示し、承認した欄のみ変更。本人編集と旧役割 MD を残し、参照と履歴を更新 |
| 不明値停止 | 顧客ID、採用図面、率の意味、税や丸めのどれかが不明 | 対象の作成・参照・売価確定を停止して人に質問 |
| 見積算定 | 税抜原価100、率20% | 粗利率なら125、上乗せ率なら120。税と丸めは確認済み規則で別計算 |
| 旧形式 | 旧 `案件/` と別用途の `AGENTS.md` が存在 | 自動移行・上書きをしない。共存または移行の選択を人に示す |
