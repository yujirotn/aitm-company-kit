# 導入前に人へ見せる構成提案のひな型

これは**提案図**であり、承認前に以下のファイルや顧客フォルダを実際に作らない。ID、日付、資料名は匿名の例。聞き取った業務と既存管理に合わせて図を描き直してから提示する。

```text
作業フォルダ/
├─ AGENTS.md                 AI が最初に読む入口
├─ 会社設定.md               合意した役割・承認・保存先
├─ 導入状態.md               未完了項目と変更履歴
├─ 役割/
│  └─ estimate-review.md    採用した担当の仕事・入力・成果物・停止条件
├─ 手順書/
│  └─ 積算確認.md            役割から参照する手順
├─ .claude/agents/           Claude Code で担当者を呼ぶ場合のみ
│  └─ estimate-review.md    作業先の役割 MD を読む定義
└─ 顧客/
   ├─ 顧客一覧.md
   └─ C001/                  中立的な顧客 ID
      ├─ README.md
      └─ 案件/
         ├─ 案件一覧.md
         └─ P001/             中立的な案件 ID
            ├─ README.md    現状・決定・未解決
            ├─ 経過ログ.md  作業履歴
            ├─ やりとり.md  顧客・業者との連絡
            ├─ 議事録/
            │  └─ 2026-10-09_01.md       打合せメモ。決定・未決・担当・期限
            ├─ 図面/
            │  ├─ README.md             図面の版台帳と採用版
            │  ├─ 2026-10-09_平面図_原本.pdf  受領図面を内容変更せず保存
            │  └─ 2026-10-12_平面図_改訂1.pdf 改訂図面を別版で保存
            └─ 見積/
               ├─ README.md             根拠・積算・提出版の台帳
               └─ 2026-10-09_業者見積_原本.pdf 業者見積の受領原本
```

実際の個人名・住所や機密のファイル名は公開リポジトリに置かない。別顧客や別案件は C002、P002 など別の枝を作る。図面と見積の原本・改訂を上書きせず、採用版は人の確認後に台帳へ記録する。

## 既存管理との対応と変更点

聞き取り済みの現状を下表に記入する。既存保存先がない場合は「なし」、不明なら「未確認」と記す。移行や複製は承認前に行わない。

| 今の保存場所・方法 | 提案する保存先・方法 | 維持する点 | 変更する点 | 既存データの扱い（そのまま/新規分から/要確認） |
|---|---|---|---|---|
| （例）共有フォルダの打合せメモ | `顧客/C001/案件/P001/議事録/` | 既存原本を保持 | 新規記録は案件ごと | 要確認 |
| （例）図面フォルダ | `顧客/C001/案件/P001/図面/` | 原本を保持 | 改訂と採用版を台帳で区別 | 要確認 |
| （例）業者見積フォルダ | `顧客/C001/案件/P001/見積/` | 受領原本を保持 | 案件ごとの版台帳を追加 | 要確認 |

## 合意の取り方

この図と対応表、採用役割、保存先、未確認項目、作成・変更するファイルを一緒に示し、**「この管理方法でいいですか？変更したいところはありますか？」**と聞く。修正希望があれば、図と対応表を直して**再提示**し、再度確認する。作業先と提案内容への**明示合意の後だけ**実ファイルの作成・変更に進む。沈黙や一部項目への回答を全体の承認とみなさない。途中で止まった場合、承認前は会話内の案として保持し、作業先には書かない。
