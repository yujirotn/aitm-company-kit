description: 会社ごとの導入を聞き取り、提案・確認して作成。未完了の再開と明示的な再設定にも対応
argument-hint: [再設定]
---

対象の作業フォルダで導入状態を確認してください。引数: $ARGUMENTS

1. 作業フォルダを表示して人に確認する。`AGENTS.md`、`導入状態.md`、`会社設定.md`、`役割/`、`.claude/agents/`、`手順書/`、`顧客/`、旧 `案件/` を読み、`docs/導入と運用.md`（`${CLAUDE_PLUGIN_ROOT}/docs/導入と運用.md`）の4状態に分類する。既存の `AGENTS.md` が別用途なら触らない。
2. 未導入なら導入文書の聞き取りをする。未完了なら既回答と既存ファイルを先に読み、残りだけ聞く。導入済みで再設定の明示がなければ現状と通常利用のコマンドを案内して終了する。旧形式・矛盾は自動移行せず、選択肢と影響を示して止まる。
3. 会社・利用者・ワークフロー・各役割の名前・担当範囲・入力・成果物・停止条件・引き渡し先・必要な手順書・保存先・承認・秘匿、見積を使うなら粗利率/上乗せ率、税、丸め、仮/確定単価を確認する。未回答を推測しない。5役は積算業務向けの初期案であり必須ではない。
4. `${CLAUDE_PLUGIN_ROOT}/docs/構成提案テンプレート.md` を参考に、作業先のディレクトリの**テキストツリー図**を示す。打合せメモ、受領図面、改訂図面、業者見積がどこに入るか、匿名の具体例で示す。既存管理との対応表で維持する点・変える点・旧データの扱いを分け、採用役割 MD と手順書の参照、未確認で止める処理、作る/変更するファイルを示す。「この管理方法でいいですか？変更したいところはありますか？」と聞く。修正希望があれば図と対応表を直して再提示し、作業先と提案内容の明示合意を得る。承認前はテンプレートのコピーを含め、実ファイルの作成・変更をしない。再設定も変更前後の差分を示して同じように合意を得る。本人の既存編集を保持し、承認された箇所だけ変える。既存ファイルを上書きしない。
5. 作業先と図・対応表への明示合意後、未存在のファイルだけ `${CLAUDE_PLUGIN_ROOT}/templates/` からコピーする。`顧客/_テンプレート/` は土台として複製するが、実顧客は作らない。`AGENTS.md`、`導入状態.md`、`会社設定.md` の該当欄を回答に沿って編集する。採用した役割ごとに `役割/_役割テンプレート.md` を基に作業先の `役割/<役割ID>.md` を新規作成し、名前・担当範囲・入力・成果物・止める条件・引き渡し先と実在する手順書への参照を `役割/<役割ID>.md` からの相対パス（例: `../手順書/<手順名>.md`）で具体化する。プラグインの `agents/` は初期案として読み、単にコピーして完了としない。`会社設定.md` と `AGENTS.md` の採用役割表から、各実体 MD へ辿れるようにする。Claude Code で担当者として使う役割は作業先の `.claude/agents/<役割ID>.md` も作り、本文で正本の `役割/<役割ID>.md` と必要な手順書を最初に読むよう記す。新しい担当者が見つからなければ Claude Code を再起動して確認する。既存ファイルは中身を読んで差分編集し、既存の `案件/` を自動移動・削除しない。途中で止まれば状態を未完了、回答済みと次の質問を残す。
6. 採用した役割 MD と参照先の手順書が作業先に実在し、役割表と一致することを確認する。未完成なら状態を未完了に保つ。必須の運用判断と役割参照が確認されたら状態を導入済みにする。変更履歴を追記し、作ったもの、未確認事項、次の `/new-client` または通常作業を伝える。実顧客情報を公開リポジトリへ入れない。
